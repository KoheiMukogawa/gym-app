# 利用状況ダッシュボード 設計

作成日: 2026-10-05

## 目的

管理者（運営）が、利用者がアプリを続けて使っているかを、アプリ内で集計値として確認できるようにする。

成功の基準:

- 管理者はヘッダーのメニューから1タップで利用状況を開ける
- 直近の利用人数と、週ごとの推移が分かる
- 個人の記録（重量・回数・メモ・種目）や、誰がいつ記録したかはアプリに出さない

対象外: 機能ごとの利用状況、利用者ごとの最終利用日、アプリを開いた日の記録（アクセス解析）、期間の切り替え、CSV出力、集計結果の保存。

## 決めたこと

- **「使った」は、その日にワークアウトを記録したこと。** アクセス解析は入れていないため、記録せずに閲覧だけした日は数えない。画面にもその旨を書く
- **週は月曜始まり、日本時間（`Asia/Tokyo`）で区切る。** 過去12週（今週を含む）を表示する
- **テスト用アカウント（`auth.users.email` が `@example.com` で終わる）は数えない。** 実SupabaseのE2Eが記録を残すため。管理者自身は数える
- **集計はDB関数でその場で計算する。** 本番は利用者7人・ワークアウト27件（2026-10-05）で、保存や定期実行は不要
- **集計値だけを返す。** `profiles` などの個人の行は返さない

## DB（migration 1本）

### `admin_usage_stats() returns jsonb`

security definer、`stable`、空search_path、完全修飾名。

1. `auth.uid()` がnullなら例外（`'ログインが必要です'`）
2. 呼び出した人が `public.admins` にいなければ例外（`'権限がありません'`）
3. 対象の利用者は「`public.profiles` のうち、`auth.users.email` が `@example.com` で終わらない人」（emailがnullの人は対象に含める）
4. 次のjsonbを返す:

| キー | 内容 |
|---|---|
| `total_users` | 対象の利用者の人数 |
| `active_7d` | `performed_at` が直近7日（`now() - interval '7 days'` 以降）のワークアウトがある対象の利用者の人数 |
| `active_30d` | 同じく直近30日 |
| `weeks` | 過去12週の配列（古い順）。各要素は下記 |

`weeks` の各要素:

| キー | 内容 |
|---|---|
| `week_start` | 週の月曜日（日本時間の日付、`YYYY-MM-DD`） |
| `active_users` | その週にワークアウトを記録した対象の利用者の人数 |
| `workouts` | その週の対象の利用者のワークアウト数 |
| `sets` | その週の対象の利用者のワークアウトに含まれるセット数 |
| `signups` | その週に `profiles.created_at` がある対象の利用者の人数 |

- 週への振り分けは `date_trunc('week', performed_at at time zone 'Asia/Tokyo')`（`created_at` も同じ）
- 記録のない週も0で埋める（`generate_series` で12週を作り、left joinする）
- 未来の日付のワークアウトは、12週の範囲外なら数えない。直近7日・30日は `performed_at <= now()` も条件にする

権限: `public`・`anon` から実行権を外し、`authenticated` にだけ付与する。advisorsの `authenticated_security_definer_function_executable` は1件増える（設計どおり。CLAUDE.mdの一覧に追記する）。

## 画面

### 入口

ヘッダーのプロフィールメニューで、管理者にだけ「届いた意見」の下に「利用状況」（`/admin/usage`）を出す。管理者の判定は既存の `useFeedbackInbox`（管理者なら件数、それ以外はnull）を使う。

### 利用状況 `/admin/usage`

ログインが必要。`AppShell` の中に置き、遅延読み込みにする。

1. 見出し「利用状況」と説明「ワークアウトを記録した日を、使った日として数えています。テスト用アカウントは含みません。」
2. 数字のカード4つ（2列×2行）: 登録者数、直近7日に記録した人、直近30日に記録した人、今週のセット数
3. 「記録した人数（週ごと）」の棒グラフ（Recharts、12本。横軸は `10/5` の形の週の開始日）
4. 週ごとの表: 週（`10/5〜`）、記録した人、ワークアウト、セット、新規登録。新しい週を上にする

状態:

- 読み込み中はスピナー。失敗したら画面内にエラーと「再試行」
- 管理者でなければ関数が「権限がありません」を返すので、そのエラーを表示する（ルートでの出し分けはしない）
- 関数が見つからない（`PGRST202`）ときは「この機能の準備中です。時間をおいてお試しください。」

エラーの文言は `feedbackMessage` と同じ規則なので、共通化して `adminMessage` として使う（ご意見の画面もこれを使う）。

## テスト

- SQL（`supabase/tests/usage_stats.sql`、`run-sql.mjs` の対象に追加）:
  - 管理者でない人・未ログインは例外、`anon` は実行できない
  - 登録者数・直近7日・直近30日が正しい。テスト用アカウントの記録と登録は数えない
  - 週の区切りが日本時間の月曜（日曜23時台と月曜0時台の日本時間の記録が別の週に入る）
  - 12週が古い順に並び、記録のない週が0になる
  - セット数・ワークアウト数・新規登録数が正しい
- 単体: 利用状況の画面（カード・表の表示、エラーと再試行）、ヘッダーのメニュー（管理者にだけ「利用状況」）
- モックE2E: メニュー → 利用状況 → カードとグラフが表示され、390px幅で横にはみ出さない
