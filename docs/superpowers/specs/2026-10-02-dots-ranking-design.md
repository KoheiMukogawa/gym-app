# DOTSランキング 設計

作成日: 2026-10-02

## 目的

BIG3の推定1RM合計（kg）だけのランキングでは、体重の重い利用者が常に上位になる。体重と係数で補正するDOTSスコアのランキングを追加し、体重の違う競技者どうしが公平に競えるようにする。体組成とBIG3を同じアプリで記録している強みを使い、記録日の体重を自動で使う。ランキングのための体重の手入力は求めない。

既存の「BIG3合計」「今月の伸び」は変更せず残す。成功の基準は、軽量の利用者もDOTSタブで上位を狙えると感じられること。

対象外: DOTSの今月の伸び、男女別ランキングや性別フィルタ、実測1RMだけのランキング、個人詳細グラフのDOTS表示、ランキングに使った体重の表示。

## データと設定

`community_profiles` に列を追加する。このテーブルは本人のみ読み書きできるRLSのため、他人の設定はランキングRPCの結果を通してしか外へ出ない。

| 列 | 型 | 意味 |
|---|---|---|
| `dots_opt_in` | boolean not null default false | DOTSランキングへの参加と体重公開への同意 |
| `dots_formula` | text null, `'male'` / `'female'` | DOTSの計算に使う係数 |

check制約で `dots_opt_in` が true なら `dots_formula` は null 不可とする。参加をオフにしても係数は残し、再参加時に選び直させない。

保存は新しいRPC `save_dots_settings(p_opt_in boolean, p_formula text)` で行う。`auth.uid()` 必須、本人の行だけを更新し、他人のuser_idを入力に取らない。不正な係数値は拒否する。`authenticated` のみ実行可能。既存の `save_glog_profile` の引数は変えない。

DOTSの同意は1つで、全体とコミュニティの両方に適用する。

- 全体ランキングのDOTS: `global_ranking = true` かつ `dots_opt_in = true` の人
- コミュニティのDOTS: そのコミュニティのメンバーのうち `dots_opt_in = true` の人

## 計算

### 共通関数

内部関数 `big3_member_stats(p_user_ids uuid[])` を作る。security definer、空search_path、完全修飾名。ユーザーごとに次を返す。

- `lifts`: 種目別の最高推定1RM
- `total`: kg合計（3種目そろった場合のみ）
- `growth`: 今月の伸び（日本時間の月初前に3種目そろった場合のみ）
- `dots`: DOTSスコア（参加者で3種目そろった場合のみ、それ以外はnull）
- `points`: 推移グラフ用の日別最高推定1RM

`global_ranking` と `community_ranking` に重複している集計SQLはすべてこの関数へ移す。2つのRPCは対象メンバーの決定と認可確認だけを行い、共通関数の結果に表示名・アイコン・自己紹介を付けて返す。kg合計・伸び・推移の結果は変更前と完全に一致させる。`global_ranking` は今と同じく `points` を空配列、`bio` を空文字で返す。

共通関数は任意のuser_idを受け取るため、PUBLIC/anon/authenticated から EXECUTE を剥奪し、クライアントから直接呼べないようにする。DOTSの値を出すかどうかの判定（`dots_opt_in`）は共通関数の中だけで行う。非参加者の体重に由来する値は関数の外に出さない。

### DOTSの手順

1. 推定1RMは既存ルールと同じ。Brzycki式、1〜10回、重量0より大、`performed_at <= now()`
2. セットごとに、記録日（`performed_at` の日本時間の日付）との差が14日以内の `bodyweight_logs` のうち最も近い日の体重を使う。差が同じなら前の日を優先する。差14日は対象、15日は対象外。該当する体重がないセットはDOTSの計算に入れない
3. セットごとのDOTS貢献 = 推定1RM × 500 ÷ (a + b·bw + c·bw² + d·bw³ + e·bw⁴)
4. 種目ごとに貢献の最大値を取り、3種目すべてに値がある場合だけ合計する。小数1位に丸める
5. kgの最高記録とDOTSの最高記録は別のセットでもよい

DOTSは合計に係数を掛ける線形の式なので、種目ごとに異なる体重で計算して足しても意味が保たれる。

係数は男性用・女性用の標準DOTS係数を使う。体重は式の有効範囲（男性40〜210kg、女性40〜150kg）に丸めてから計算する。係数は実装時に公開資料と照合し、既知の計算例と一致することをテストで確認する。

体重の検索は既存の主キー `(user_id, recorded_on)` を使う。現在の規模では新しいインデックスを追加しない。

## 画面

### ランキング

全体ランキング（`GlobalRanking`）とコミュニティ内ランキング（`CommunityPanel`）の両方で、タブを「BIG3合計｜今月の伸び｜DOTS」にする。タップ領域は56px以上。

DOTSタブ:

- `dots_opt_in` の参加者だけを並べる。RPCは参加有無が分かる値として `dots_opt_in` を各メンバーに含める
- スコアは `412.3` のように単位なしで表示する。kg表示の付与は指標ごとに切り替える
- 参加していてもスコアがない人は順位「—」で末尾に表示する
- 順位付けは既存の `rankMembers` に `'dots'` を追加して共通化する。同点は同順位

ランキングの下に、自分の状態に応じた案内を出す。

| 自分の状態 | 案内 |
|---|---|
| 参加していない | 「DOTSランキングへの参加はプロフィールで設定」（プロフィールへのリンク） |
| 参加しているがスコアなし | 「3種目それぞれ、記録日の前後14日以内の体重が必要です」（体組成タブへのリンク） |
| スコアあり | なし |

常に表示する説明: 「記録日の前後14日以内の体重でDOTSを計算します。体重の公開に同意した人だけ表示しています。」

`Member` 型に `dots: number | null` と `dots_opt_in: boolean` を追加する。コミュニティの個人詳細グラフは変更しない。

### プロフィール

「全体ランキングに参加」の下に置く。

- 「DOTSランキングに参加」のトグル
- オンのとき「計算に使う係数: 男性用／女性用」の選択を表示し、未選択では保存できない
- 説明: 「記録日の前後14日以内の体重でスコアを計算します。スコアとBIG3合計から体重が推定できるため、参加する場合は体重の公開に同意したことになります」

### エラー

通信エラーは空状態と同じ表示にしない。ランキングの読み込み失敗は画面内にエラーを残して再試行ボタンを出す既存パターンに合わせる。DOTS設定の保存失敗もプロフィール画面内にエラーを残す。

## テスト

SQL（PGlite）:

- 最も近い日の体重を使う。差が同じなら前の日を優先する。差14日は対象、15日は対象外
- 3種目のうち1つでも体重付きのセットがなければDOTSはnull
- 非参加者はDOTSがnullで、体重に由来する値が返らない
- 女性用係数、有効範囲外の体重の丸め、既知の計算例との一致
- `authenticated` から `big3_member_stats` を直接実行できない
- `save_dots_settings` は本人の行だけを更新し、参加オンで係数なしを拒否する
- 既存のkg合計・伸び・推移の結果が変更前と一致する
- 全体のDOTS対象は全体ランキング参加者かつDOTS参加者に限られる

UI（Vitest / Testing Library）:

- `rankMembers` のDOTS順位付け（同点、null）
- 両ランキングのDOTSタブ切り替え、参加者だけの表示、単位なし表示
- 自分の状態に応じた案内3パターン
- プロフィールで参加オン時に係数選択が必須になること、保存の成功と失敗
- ランキングとDOTS設定の通信エラー表示と再試行

## 公開時の注意

本番DBへのmigration適用は、既存の `global_ranking` / `community_ranking` を置き換える。適用前にローカルで既存kg結果の一致を確認する。既存利用者は全員 `dots_opt_in = false` で始まり、同意するまで体重由来の値は誰にも表示されない。
