# 投票（POLL-01）

利用者と一緒にアプリの方向性を決めるため、選択式の投票を出す。最初の投票はアプリの名前（Glog／BARBELL CLUB、2026-11-02〜11-05 23:59 JST）。

## 利用者の体験

- 受付中でまだ投票していない投票は、起動後に「マッチョ会議」のシートで1回だけ出す（投票ごと。出した投票のIDを端末の `glog:poll-sheet:<userId>` に残す）。記録中・投票の画面では出さない。お知らせのシートがある起動では、お知らせを閉じてから出す（`announcements/sheetState.ts`）。
- 選択肢を選んで「投票する」→ 確認（変えられないこと）→ 投票。シートはそのまま結果に変わる。
- ヘッダーのメニュー（サポート）の「投票」から投票の画面（`/polls`）を開ける。まだ投票していない受付中の投票があると「受付中 N」。
- 結果は投票した人と、締め切り後はすべての人に、選択肢ごとの票数と割合だけを出す。誰がどれを選んだかは出さない。
- 投票の変更・取り消しはできない。

## DB（`20261102120000_polls.sql`）

- `polls`（質問・説明・開始・締め切り）、`poll_options`（投票ごとの選択肢ID・表示名・順番）、`poll_votes`（投票と利用者で1行）。
- 利用者は始まった投票と選択肢、自分の票だけを読める。票の書き込みは `vote_poll`（security definer）だけ。update・delete の権限はない。
- `list_polls()` は始まった投票を、受付中を先に返す。票数は本人が投票済みか締め切り後だけ返し、それ以外は null。
- `vote_poll(p_poll_id, p_option_id)`：未ログイン・開始前・締め切り後・ない選択肢・投票済みはそれぞれ理由を返して断る。
- 票は退会（profiles の削除）とともに消える。
- 最初の投票はこのmigrationで入れる。締め切りは翌日0時（`ends_at` は含まない）で、画面には1分前（23:59）を出す。

## これから

- 管理画面で投票を作る（質問・選択肢・期間）。そのときは `admin_create_poll` などの関数にし、管理者（`public.admins`）だけが実行できるようにする。
- 「その他（自由入力）」の回答。
