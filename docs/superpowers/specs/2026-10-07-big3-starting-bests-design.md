# BIG3のベストを入れて始める 設計

作成日: 2026-10-07

## 目的

筋トレMemoなどから乗り換えてきた人が、過去の記録を全部移せなくても、登録した日からBIG3合計・推定1RM・ランキング・グラフの起点が埋まった状態で始められるようにする。「記録がゼロだから面白くない」をなくす。筋トレMemoには書き出し機能がなく（`docs/kintore-memo-migration.md`）、過去の記録を持ってこられないことが乗り換えの一番の壁になっている。背景は `docs/growth-architecture.md`。

成功の基準:

- 乗り換えてきた人が、登録から1分以内にBIG3合計とランキングの入口を見られる
- 乗り換えではない新規の人は、カードを閉じれば二度と見ない
- 記録画面と記録中の操作は一切変わらない

対象外: BIG3以外の種目のベスト入力、過去の記録の一括取り込み、筋トレMemoのデータの読み取り、この機能専用の計測イベント、起動時のお知らせ。

## 決めたこと

- **入れたベストは、選んだ日の普通の記録（ワークアウトのセット）として保存する**（本人が案Aを選択）。カレンダー・履歴に出て、いつもの履歴の編集画面で直せる・消せる。BIG3・ランキング・DOTS・グラフ・ホームの棒グラフは記録から計算しているので、そのまま反映される
- **DB・migration・ランキングのSQLは変えない。** 履歴編集の既存の処理を組み合わせる
- **セットのメモは空のまま。** 普通の記録と見分けがつかない形にする
- 利用状況の集計（`admin_usage_stats`・`admin_growth_stats`）では、その日が「記録した日」として1日分入る。影響は小さいので許容する（本人了承）

## 画面の流れ

### 入口（ホーム）

- **BIG3の3種目とも推定1RMがない人（`snapshot.lifts.*.allTimeE1rm` がすべて `null`）にだけ**、ホームのカレンダー/BIG3の下、「今日のトレーニング」の上にカードを出す
  > **前のアプリから乗り換え？**
  > BIG3のベストを入れると、今日から合計・推定1RM・ランキングが使えます
  > ［ベストを入れて始める］ ［閉じる］
- 「ベストを入れて始める」は `/big3/start` へ移る
- 「閉じる」はユーザーごとに端末へ保存し（`localStorage`、キー `glog:big3-start-dismissed:<userId>`）、以後は出さない。保存できない環境（プライベートモード等）では、その画面を開いている間だけ消える
- BIG3の記録が1つでも入れば、条件を満たさなくなるので自然に消える
- **BIG3の取得に失敗したとき・読み込み中は出さない。** 失敗を「記録なし」と取り違えない
- タップ領域は56px以上

### 入力画面（`/big3/start`、`AppShell` の中、ログイン必須、遅延読み込み）

- スクワット・ベンチプレス・デッドリフトの3行。各行は「重量 kg」と「回数」の入力欄（`inputMode="decimal"` / `numeric`）。回数の初期値は `1`
- 各行の下に推定1RM、画面の下にBIG3合計（入力のある種目の合計。3種目そろっていなければ「◯種目の合計」と明記）を入力と同時に表示する。計算は既存の `estimateOneRepMax`（Brzycki、1〜10回）
- 3種目すべては必須にしない。1種目以上で保存できる
- **「いつ頃の記録？」**：日付の入力欄。初期値は今日（`localDate()`）、`max` は今日
- 入力のチェック（欄の下に理由を出し、不正な欄があれば保存ボタンを押せない）:
  - 重量: 0より大きく9999.9以下、小数1桁まで（`validateSet` と同じ範囲。0kgは推定1RMにならないので不可）
  - 回数: 1〜10の整数。11以上は「11回以上は推定の誤差が大きいため使えません。10回以下の記録を入れてください」
  - 日付: 今日以前の正しい日付（`workoutDateISO` と同じ判定）
  - 重量と回数のどちらかだけが入った行は「重量と回数の両方を入れてください」
- ［BIG3を登録］で保存し、成功したら `/big3` へ移ってトースト「BIG3を登録しました」
- 種目名は、その人のBIG3の設定（`snapshot.lifts.*.exerciseName`）を表示する。BIG3の種目が解決できない種目（`exerciseId` が `null`）の行は入力欄を出さず、「BIG3の設定で種目を選んでください」と `/big3` への案内を出す
- 保存済みの記録がある場合（別の端末で入れた後など）でも、この画面は使える（普通の記録として追加されるだけ）

## 保存

新しい関数 `saveStartingBests(userId, date, entries)` を `src/features/strength/` に置く。`entries` は `{ exerciseId, weightKg, reps }[]`（入力のある種目だけ）。

ワークアウトのID（`ownWorkoutId`）とセットのID（種目ごとに1つ）は、入力画面を開いたときに一度だけ端末で生成し、再試行でも同じIDを使う。

1. `findWorkoutOnDate(userId, date)` でその日のワークアウトを探す。あればそれを保存先にし、なければ `createDatedWorkout(userId, ownWorkoutId, date)` で作って保存先にする（1日1件のルールは既存どおり。`createDatedWorkout` は重複IDを既存として扱い、日付が違えば合わせる）
2. 保存先のセットを `fetchEditableWorkout` で読み、**今回のセットID以外の**セットから種目ごとの `set_index` の最大値を求める（再送で自分のセットが既に入っていても番号が飛ばない）
3. 種目ごとに `saveEditableSet(保存先, { id, exercise_id, weight_kg, reps, set_index: 最大値 + 1, note: null })`。IDでupsertするので、再送では同じセットが上書きされる（保存先が変わればセットもそちらへ移る）
4. 保存先が `ownWorkoutId` 以外で、前の試行で `ownWorkoutId` を作っていた場合は、`deleteWorkoutIfEmpty(ownWorkoutId)` で空になったワークアウトを消す（失敗後に日付を変えて再試行したとき、前の日に空のワークアウトを残さない。中身があれば消さない）

**再送しても二重にならない:** 上のとおり、同じIDの再利用とupsertで、1回目が途中で失敗しても2回目で重複しない。保存がすべて成功したら画面を離れるので、IDの再利用は1回の登録の中に限られる。

**失敗したとき:** エラーは画面内に `role="alert"` で残し、［再試行］を出す。入力した値は消さない（既存のパターン）。通信エラーを入力エラーと同じ見た目にしない。

## テスト

**単体**

- 検証と計算: 重量×回数 → 推定1RM、入力のある種目だけの合計、回数1〜10・重量・日付・片方だけの行のチェック
- `saveStartingBests`: その日に記録がなければ作り、あれば追加する。同じ種目のセットがあれば続きの番号。1回目が途中で失敗して再送しても、同じIDで二重にならず番号も飛ばない。失敗後に日付を変えて再試行すると、前の試行で作った空のワークアウトが消える
- カード: 3種目とも空の人にだけ出る。1種目でもあれば出ない。「閉じる」のあとは出ない（ユーザーごと）。取得失敗・読み込み中は出ない
- 入力画面: 1種目だけで保存できる。不正な入力では保存できない。保存の失敗が画面に残り、入力が消えず、再試行で保存できる。成功で `/big3` へ移る

**モックE2E（320 / 375 / 390px）**

- 記録ゼロでログイン → ホームのカード → 2種目を入力 → 登録 → `/big3` に合計と推定1RM → ホームに戻るとカードが消えている
- 横にはみ出さない。主な操作のタップ領域が56px以上
