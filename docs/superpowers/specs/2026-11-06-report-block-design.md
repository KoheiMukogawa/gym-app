# 通報・ブロック 設計

作成日: 2026-11-06（App Storeの審査ガイドライン1.2「利用者が作るコンテンツ」への対応）

## 目的

ほかの利用者の名前・アイコン・ひとことに不快なものがあったとき、利用者が **通報** して運営に知らせ、**ブロック** して自分の画面から消せるようにする。App Storeの審査では、利用者の投稿がほかの人に見えるアプリに次の4つを求めている。

| 審査の要件 | Glogでの対応 |
| --- | --- |
| 不適切な投稿を防ぐ仕組み | 名前・ひとこと・コミュニティ名に禁止語のチェック（この設計） |
| 通報の仕組みと、すみやかな対応 | 通報（この設計）と、管理者の画面での対応（この設計） |
| 迷惑な利用者をブロックする手段 | ブロック（この設計） |
| 連絡先の公開 | 利用規約・プライバシーポリシーの `glog.app.help@gmail.com`（済み） |

利用規約の第3条（禁止事項）と第6条（利用の停止：投稿内容の変更・削除、アカウントの削除）は、すでにこの対応を含んでいる。審査では「不適切な投稿を許さない」ことに同意させる規約を求められる。新規登録の画面は「登録すると利用規約に同意したものとみなす」と出しているので、変えない。

## ほかの人に見えるもの（対象）

| 内容 | 見える場所 | 見える相手 |
| --- | --- | --- |
| 表示名・アイコン（写真を含む） | 全体ランキング、コミュニティのランキング、メンバーの詳細 | 全体ランキングに参加した人は全員、コミュニティは同じメンバー |
| ひとこと（bio） | コミュニティのメンバーの詳細 | 同じコミュニティのメンバー |
| コミュニティ名 | コミュニティの一覧 | そのメンバー |

ご意見は本人と管理者だけ、投票は選択肢を運営が作るので、対象外。

## 決めたこと

### 通報

- **通報は「人」に対して行う。** メンバーの詳細（`MemberDetail`）の下の「通報する」（隣に「ブロックする」）。シートの中で、理由の選択 → 送信 → ブロックの確認と切り替わる。理由を1つ選ぶ（不適切な名前／不適切な画像／不適切なひとこと／なりすまし／その他）＋任意の詳細（500文字まで）
- **通報した時点の名前・アイコン・ひとことを、そのまま保存する（`snapshot`）。** 通報の後で本人が書き換えても、管理者は何が通報されたかを確かめられる
- **通報できるのは、自分の画面に出ている人だけ。** 全体ランキングに参加しているか、同じコミュニティにいる人。それ以外のIDを送られたら拒否する（利用者のIDを総当たりで確かめられないように、拒否の文言は「この操作はできません」に統一）
- **同じ相手への未対応の通報は1件にまとめる。** 2回目は理由と詳細を上書きし、時刻を進める。自分自身は通報できない
- **送りすぎを防ぐ。** 1人あたり1日20件まで（ご意見の `feedback_rate_limit` と同じ考え方）
- **送った後に「この人をブロックしますか？」と続けて聞く。** 通報だけで終えてもよい
- 通報したことは相手に知らせない

### ブロック

- **ブロックは片方向。** ブロックした人の画面からだけ、相手が消える。相手には知らせず、相手の画面は変わらない
- **消える場所:** 全体ランキング、コミュニティのランキング、コミュニティの人数表示。DBの `global_ranking()`・`community_ranking()` が、ブロックした相手の行を返さない（名前もアイコンも端末に届かない）。順位は端末で数え直すので、ブロックした人の画面では順位が詰まる
- **同じコミュニティにいても、コミュニティからは外さない。** 外せるのは作成者だけにしたいが、今は作成者がメンバーを外す機能がない（下の「今回はやらないこと」）
- **ブロックの解除:** プロフィールの「アプリ設定」の下に「ブロックした人」。名前とアイコンを並べ、「解除」を押すと戻る
- **自分自身と、紹介ページの見本（`/demo`）では「通報する」「ブロックする」を出さない**

### 不適切な投稿を防ぐ（禁止語）

- **表示名・ひとこと・コミュニティ名を保存するときに、DBで禁止語を確かめる。** 当てはまれば「使えない言葉が含まれています」で保存しない。利用者は `community_profiles` を直接更新できる権限を持っているため、関数ではなく表のトリガー（`community_profiles_banned_words`・`communities_banned_words`）で確かめる。書き換えた欄だけを確かめる（プロフィールの保存は `insert … on conflict do update` なので、追加のときもすでにある行と比べる）ので、禁止語を後から足しても、既存の名前のままDOTSの設定などは保存できる
- **禁止語はDBの表 `banned_words` に置き、管理者がSQL Editorで `insert into public.banned_words(word) values ('…')` で足す。** 比べる前に全角・半角、大文字・小文字、カタカナ・ひらがなをそろえ、空白と記号を除く（`ban_normalize`。足した語も自動でそろえて保存する）。部分一致で比べるので、ほかの言葉の一部になりやすい短い語は入れない。最初は性的・差別的・攻撃的な語を44語（適用直後に「ちんこ」「まんこ」が「ちん こうへい」など名前の境目に当たったため外し、「おまんこ」にした。`20261106130000_banned_words_fixes.sql`）。語を足す前に、既存の名前・ひとこと・コミュニティ名に当たらないか確かめる
- **新規登録の名前:** 登録の処理（`handle_new_user`）で禁止語に当たったら、登録は止めずに名前を初期の「Glogユーザー」にする（登録の失敗は原因が分かりにくいため）。あとでプロフィールから直せる
- **写真は自動では確かめない。** 通報と、管理者による削除で対応する（費用のかかる画像判定のサービスは使わない）

### 管理者の対応

- **ヘッダーのメニューに「届いた通報」（`/admin/reports`）。** 管理者だけに出す。未対応の通報があると、アイコンの赤い輪（今は未読のご意見で出している）も出す
- **1件ごとに、通報の内容（理由・詳細・通報時の名前・アイコン・ひとこと）と、今の名前・アイコン・ひとことを並べる**
- **できること（`admin_resolve_report`）:**
  - **問題なし**：何も変えずに対応済みにする
  - **プロフィールを初期化**：名前を「Glogユーザー」、アイコンを `muscle`、ひとことを空にする。写真のファイルは管理者がSupabaseのダッシュボードで消す（今の手順と同じ）
  - **ランキングから外す**：初期化に加えて、全体ランキングへの参加をやめさせる（`global_ranking = false`）。それでも続く場合のアカウントの停止・削除は、Supabaseのダッシュボードで行う
- 同じ相手への未対応の通報は、まとめて対応済みにする
- **24時間以内に対応する**ことを目安にする（審査で求められることが多い）。メール・プッシュの通知はないので、管理者が毎日アプリを開いて赤い輪を確かめる運用にする

## DB（migration `20261106120000_reports_blocks.sql`）

- `user_reports`：`id`・`reporter_id`・`target_id`（どちらも `profiles` を参照、退会で消える）・`reason`（チェック制約で5種類）・`detail`（500文字まで）・`snapshot`（jsonb）・`created_at`・`resolved_at`・`resolution`（`dismissed`／`reset`／`removed`）。利用者は直接読み書きできない（RLSは有効でポリシーなし、関数からだけ）
- `user_blocks`：`blocker_id`・`blocked_id`（主キーは2つの組、自分自身は不可）・`created_at`。本人の行だけ読める・消せる（RLS）
- `banned_words`：`word`（そろえた形で保存）。利用者は読めない
- 関数（security definer、`search_path` は空、anonから実行不可）:
  - `report_user(p_target, p_reason, p_detail)`、`block_user(p_target)`、`unblock_user(p_target)`、`list_blocked_users()`
  - `admin_list_reports()`、`admin_open_report_count()`、`admin_resolve_report(p_target, p_action)`
  - `ban_normalize(text)`・`has_banned_word(text)`・`can_see_member(uuid, uuid)`（内部用、利用者からは実行不可）
- 作り直す関数: `global_ranking()`・`community_ranking(uuid)`（ブロックした相手を除く）、`handle_new_user`（禁止語）
- 退会（`delete_my_account`）は外部キーの連鎖で通報・ブロックの行も消える。通報された人が退会したら、その通報も消える

## プライバシーポリシー

改定日を2026-11-06（実際の公開日）にして、次を追記する。
- 通報の内容（理由・詳細）と、通報した時点の相手の名前・アイコン・ひとことを保存し、管理者が確認すること
- ブロックした相手を保存すること

## 今回はやらないこと

- コミュニティの作成者がメンバーを外す機能（要望があれば別に作る）
- 写真の自動判定、記録（重量・回数）の通報
- 管理者への通知（メール・プッシュ）
- お知らせ（`announcements.ts`）への追加。通報・ブロックは困ったときに使う機能なので、起動時のシートでは知らせない
