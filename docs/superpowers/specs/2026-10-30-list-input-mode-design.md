# 記録画面の「一覧入力」モード 設計

作成日: 2026-10-30

## 目的

筋トレMemoから移ってくる人や「数字を打って一覧で入れたい」人のために、記録画面（REC-02）の入力方法を「ダイヤル」と「一覧」から選べるようにする。今のダイヤル方式は残し、既定もダイヤルのまま。

参考にするのは「セットを表の行として並べ、キーボードで打つ」という入力の形だけ。筋トレMemoの配色・見た目・アイコンは真似しない（Strong・Hevyなどでも一般的な形）。画面の中では「筋トレMemo方式」とは呼ばず「ダイヤル／一覧」と呼ぶ。

対象外: 履歴の編集画面（HIS-02）、種目を選ぶ画面（REC-01）、インターバルタイマー、lbs表示、DB変更。

## 決めたこと

- **行ごとの✓（完了ボタン）は作らない**（本人の判断。手数と工数を増やさないため）
- **保存は記録画面を抜けるときにまとめて行う**。抜けるとは次のどれか:
  - 「種目を変える」
  - 「記録を終了」
  - ルーティンの「前の種目」「次の種目へ」
  - アプリが裏に回ったとき（`visibilitychange` で `hidden`）。iPhoneのホーム画面アプリは裏に回ったまま終了されることがあり、ここで保存しないと記録が消えるため
- 「グラフ」へ移るのは抜けたことにしない（記録画面は裏で保持され、入力は残る）
- 打っている途中の値は、今の下書き（`persistence.ts` の localStorage）に入れて、再読み込みしても消えないようにする

## 画面（一覧モードのREC-02）

- 上部（種目名・グラフ・記録を終了）、前回の記録カードは今と同じ
- その下に、今の種目の表:

  | セット | 重量 | 回数 | 推定1RM |
  |---|---|---|---|
  | 1 | [ 100 ] kg | [ 5 ] 回 | 112.5kg |
  | 2 | [ 100 ] kg | [ 5 ] 回 | |
  | ＋ セットを追加 | | | |

- 重量は `inputMode="decimal"`、回数は `inputMode="numeric"`。タップで数字キーボードが出る
- **「＋ セットを追加」は直前の行の重量・回数を入れた行を足す**。筋トレMemoの「前の値を写す」ボタンの代わりで、行ごとのボタンは置かない。1行目の初期値は、今の「次のセットの初期値」（前回の記録→既定値）と同じ
- メモ: 行をタップして開く今のメモ欄をそのまま使う
- 削除: 左スワイプ（今と同じ）
- ほかの種目のセットは、今と同じく表の下に保存済みの一覧として並ぶ
- 入力のチェックは今の `validateSet` と同じ。0回のセットも入れられる

## 保存の流れ

画面を抜けるときに、今の種目の行と、最後に保存した内容を比べる:

- 新しい行 → 追加（`saveEditableSet` のupsert。IDは行を作ったときに端末で決めるので、再送しても重複しない）
- 値が変わった行 → 更新（同じupsert）
- 消した行 → 削除（`removeWorkoutSet`）
- 重量・回数の両方が空の行 → 保存しない
- どちらか一方だけの行 → 抜けるのを止め、その行に「重量と回数の両方を入れてください」を出す（アプリが裏に回ったときは止められないので、その行だけ下書きに残す）

ワークアウトの作成（1日1件）、保存失敗時の「未保存・再試行」、終了時の空ワークアウトの削除は、今の `persist` の仕組みを使い回す。保存に失敗したら画面を抜けずにその場に残り、再試行できるようにする。

## 切り替え（本人が決定）

- 記録画面の上部（「ダイヤル／一覧」）、ヘッダーのメニュー（「記録の入れ方」）、プロフィール（マイページ）の3か所
- 設定は端末ごとに保存（localStorage、`glog:log-input-mode:<userId>`）。DB変更なし。どこで変えてもほかの画面にすぐ伝わる
- 一覧からダイヤルに切り替えるときは、今の種目の行を先に保存する。保存できなければ切り替えない
- **一覧入力の公開より後に登録した人には、最初に記録画面を開いたとき入力方法を選ぶシートを出す**（`LIST_MODE_RELEASED_AT`、閉じられない）。筋トレMemoなどから移ってきた人が慣れた形を選べるように。公開前からの利用者はダイヤルのままで、お知らせで知らせる

## 実装

- `src/features/workout-log/listRows.ts`：行の型、行と保存済みのセットの比較（`planListSave`）
- `src/features/workout-log/ListSetTable.tsx`：一覧の表
- `src/features/workout-log/inputMode.ts`：入力方法の設定と、最初に聞くかどうか
- `LogPage.tsx` の `flushList`：保存（`saveEditableSet`・`removeWorkoutSet` を使い回す）
- 自重種目はアシストのマイナスを打てるよう、加重欄だけ `inputMode="text"`

## 改訂（2026-10-30、本人の指示）

本人の判断で、一覧モードのREC-01・REC-02を筋トレMemoの画面構成に合わせた（色はGlogの配色のまま）。上の「画面」「切り替え」のうち、次の点はこちらが正しい。

- **記録画面の上部の切り替えは削除**。切り替えはメニューの「記録の入れ方」とプロフィールだけ
- **REC-01（一覧モード）**：今日の記録があれば上に「今日の記録」（合計種目数・セット数・レップ数・負荷量と、種目ごとのカード。カードを押すとその種目に戻る、`TodaySummary`）。その下に部位ごとのカード（見出しは部位名だけ。最後に記録してからの時間は本人の判断で出さない。表示する設定の種目をすべて（本人の判断で3種目に絞らない）、「種目を追加」、`GroupedExercisePicker`）。「種目を追加」は今までの種目選択（「部位・種目を追加」ボタンは本人の判断で置かない）（`ExercisePicker` の表示の管理）を開く。ダイヤルの人は今までの画面のまま。マイルーティンは本人の判断で出さない（ダイヤルの人には今までどおり出す）
- **REC-02（一覧モード）**：上部は左上の「‹」（保存して今日の記録へ戻る）と中央の種目名だけ（「記録を終了」は出さない。終えるのはREC-01の「‹」）。トロフィーとインターバルタイマーは本人の判断で置かない（種目のグラフへは前回の記録の「グラフ」から）。前回の記録（日付・グラフ・全セット・「前回の記録を写す」）に続けて表（セット・重さ・回数・RM・補助、各行の下にメモ）。重さ・回数・メモの左の丸い矢印で上の行（1行目は前回の1セット目）の値を写す。赤い＋で空の行を足す。ほかの種目のセットはREC-02には出さず、REC-01の今日の記録に出す
- **新しい行は空**。前の版は初期値を入れていたが、種目を開いただけで行っていないセットが保存されるため
- **補助**：チェックすると、メモの先頭に「補助あり」を付けて保存する（筋トレMemoから取り込んだ記録と同じ形）。読み込むときは先頭の「補助あり」を印に戻す
- 360px未満では、推定1RMをメモの行の右に回す

### 2026-10-30 再改訂（REC-01）

- 一覧モードのREC-01は、筋トレMemoの日付の画面と同じ「今日の記録」にした。見出しは左上の「‹」（ホームに戻る。記録を終えたことにする）と中央の日付（「次はどの種目？」「記録を終了」は出さない）、その下に種目ごとのカード（今日の合計の4つの枠は本人の判断で出さない）（見出しを押すとその種目を開く、セットは左にスワイプで削除（ダイヤルの記録画面と同じ。ごみ箱は置かない）、カードの下の＋でその種目にセットを足す）
- 種目の追加は右下の赤い＋（REC-02のセットを足す＋と同じボタン `add-list-row`、`AddFab`）。押すと「種目を選択」（部位ごとのカード）を開き、「戻る」で今日の記録に戻る。まだ記録が無い日は、最初から種目を選択を出す
- 上部の赤い帯は本人の判断で使わない。マイルーティン・部位の見出しの時間表示も出さない
- 今日の記録の画面でセットを消せるので、種目を開くたびに保存済みのセットから行を作り直す

### 2026-10-30 再改訂（REC-02）

- 補助のチェックは本人の判断でなくした。メモの「補助あり」は普通のメモとしてそのまま見せる
- 重さ・回数の欄は⊗で消せる（消したあと、その欄に入力を続けられる）
- 右上の「kg｜lbs」で単位を切り替える（端末ごと、`glog:weight-unit:<userId>`）。DBにはいつもkgで保存し、表示と入力だけ換算する（lbs→kgは小数1桁に丸める。100kgは220.5lbsと表示し、そのまま戻すと100kgになるので送り直さない）。切り替えると、打ってある重さもその単位に書き換える。前回の記録・RMも同じ単位で出す。REC-01の今日の記録はkgのまま

### 2026-10-30 管理者の画面ID・ボタンID

- ヘッダーの画面IDと、各ボタンの横のボタンIDは、押すとクリップボードにコピーし、「〜をコピーしました」と出す（`src/features/admin/copyId.ts`）。ボタンIDの札は押せるようにしたので、ボタンの端に重なっていると、その部分はボタンではなく札が押される（管理者が画面IDを表示しているときだけ）
