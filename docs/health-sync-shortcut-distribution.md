# 配布用ヘルスケアショートカットの準備

2026-10-03。連携画面を3段階に整理。配布用ショートカット本体・iCloudリンクは未作成。iPhone実機での読み取り・送信確認も未実施。この文書は作成者用の準備手順であり、追加できるファイルではない。

## 配布するもの

1本の「Glog ヘルスケア同期」で、初回の1日、過去の期間、最近4日を選べる構成にする。送信先は `https://lombbjpiftuqkacasmzg.supabase.co/functions/v1/body-metrics` に固定。個人の連携キーだけを読み込み時の質問で設定する。共有する原本のキー欄・デフォルト回答は空にする。

元の処理は [既存の作成手順](health-sync-shortcut.md) にある。期間を日ごとに処理し、その日の最新体重・同日の最新体脂肪率だけを採用する契約は維持する。初版の簡単設定は `keep` 固定とし、既存記録の上書きは手動手順に残す。

## iPhoneで一度だけ行う作成作業

1. 原本「Glog ヘルスケア同期」を新規作成。先頭に送信先の「テキスト」→ URL変数、空の「テキスト」→ Token変数を置く。
2. 期間入力に「メニューから選択」を使う。「1日分を確認」は日付入力1つからStartとEndを同じ日にする。「過去の期間」は開始日と終了日を入力。「最近4日」は今日の開始時刻から3日戻したStartと、今日のEndにする。すべてModeは `keep`。
3. 既存手順の「Glog 期間同期」の月分割・日ごとの検索を組み込む。別ショートカットへの依存は残さない。月送信ブロックを親の8・14の両方へ直接置く。子の「停止して出力」は使わず、失敗・件数不一致はこの原本そのものを停止させる。成功した月だけ次へ進む。
4. 初回の1日分ではPOST直前に日付・kg・%を端末内で確認できるようにする。確認で中止したらPOSTしない。期間・最近4日では毎日の入力を要求せず、許可済みの検索・送信を使う。キーや本文を通知・ログへ入れない。
5. Token用テキストのパラメータに読み込み時の質問「Glogの連携キーを貼り付けてください」を追加。デフォルト回答は空。名前・モード・送信先の追加質問は不要。

アクション名・検索の境界・kg/%の選択は実機で確かめる。Windowsから未確認のワークフローファイルを生成して配布済みと扱わない。

## 共有と実機確認

1. 原本を共有する前にキー欄を空にする。原本の全アクションに個人キーや個人の測定値が残っていないことを端末内で確認。
2. ショートカットの共有 →「iCloudリンクをコピー」。iPhoneだけで共有できる。リンクは原本を公開するため、個人用に設定したコピーから共有しない。
3. 共有リンクから検証用コピーを追加し、読み込み時の質問で本人のキーを設定する。元から端末にある原本の成功だけで、配布版の成功と扱わない。
4. 本人が送信を明示許可した少数日のみで、体重だけの日・体脂肪率ありの日・同日最新値・月境界・kg/%・日付を確認。再送で重複せず、既存行を変更しないこと、失効後は成功扱いにならないことを確認。共有ログにキー・測定値・送信本文を残さない。
5. 最近4日の自動実行は別途iPhoneのオートメーションで設定する。原本のメニューに依存しないよう、ショートカット入力 `daily` の場合は最近4日を選ぶ分岐を用意し、オートメーションから `daily` を渡す。毎日の時刻・ロック状態で動くかは実機で確認する。アプリ画面のボタンからオートメーション作成まで完了したと扱わない。

## アプリへのリンク設定

追加したコピーで上記の確認が完了してから、`src/features/body/healthSyncShortcut.ts` を更新する。

```ts
export const healthSyncShortcut: { importUrl: string; verifiedOn: string } | null = {
  importUrl: /* 検証した、秘密情報を含まないiCloud共有リンク */,
  verifiedOn: /* 実機確認日 YYYY-MM-DD */,
}
```

この例はリンク未入力の説明用。実際のコードでは文字列を設定する。URLは `https://www.icloud.com/shortcuts/` と32桁のIDだけとし、query・fragment・キーを付けない。現在の値は `null` なので「簡単追加は準備中」と手動手順を表示する。検証済み設定がある時だけ「同期ショートカットを追加」が表示される。クリックやキー発行だけで連携完了表示にしない。

リンク設定後はユニットテスト、モックE2E、TypeScript、PWAビルドを再確認。本番公開は本人のデプロイ指示後に行う。DB・Edge Functionの変更は今回不要。
