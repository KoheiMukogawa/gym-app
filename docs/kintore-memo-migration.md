# 筋トレMemoからの記録移行（本人分・一度きり）

作成日: 2026-10-02 / 状態: 手順の合意済み、スクリーンショット未受領

## 決まっていること

- 対象は本人（と身内数人）の記録を一度だけ移すこと。アプリに取り込み機能は作らない
- 筋トレMemo（App Store id1109688815）にはCSV等の書き出し機能がない（本人の端末で確認済み）。プレミアムのオンラインバックアップは筋トレMemo専用のため使わない。バックアップ形式の解析は規約上のおそれがあるので行わない
- 履歴画面のスクリーンショットをエージェントが画像として読み、記録に起こす
- 将来の一般公開では「画像を送ってもらい有償で移行を代行する」案がある。今回1日分あたりの手間を記録しておき、料金の根拠にする。公開時はプライバシーポリシー（健康情報の利用目的・保管期間・削除）、特定商取引法の表記、支払い方法（アプリ内課金の要否）を確認する

## 手順

1. 試し読み: 1〜2枚で読み取り精度を確かめる。読めない値は推測せず本人に聞く
2. 全件の読み取り: `日付, 種目名(筋トレMemoの表記), セット番号, 重量kg, 回数, メモ` のCSVに起こす。lb表記ならkgへ換算し、換算したことを列で残す
3. 種目の対応表: 筋トレMemoの種目名 → Glogのプリセット種目（`exercises.is_preset`、`name_normalized` で照合）。対応がない種目は本人専用のカスタム種目として作る（`is_preset=false`, `created_by=本人`）
4. 本人確認: CSVと対応表を見せてOKをもらう
5. 取り込み: 本番DBへの書き込み直前に、本人の明示的な許可を改めて取る。1トランザクションで実行し、失敗時は全体を取り消す
6. 検証: 取り込み件数、日数、BIG3の最高推定1RMがCSVと一致することを確かめる。ランキングに反映されるので全体・コミュニティの表示も確認する

## 取り込みのDB上の注意

- `workouts`: 1ユーザー1日（日本時間）1件。0010で同日の記録を統合済みで、アプリも同日の記録を1件にまとめる前提。`performed_at` は日本時間の日付の昼など、日付がずれない時刻にする
- 取り込み先の日にGlogの記録がすでにある場合は、別の `workouts` を作らずその日の記録にセットを追加し、`set_index` を種目ごとに続き番号にする。重複の扱いは本人に確認する
- `workout_sets`: `set_index >= 1`、`reps >= 1`、`weight_kg numeric(5,1)`。自重種目（`exercises.is_bodyweight`。チンニング、ディップス）は追加重量を記録し、アシストは負の値。メモは `note`（200文字以内）
- 未来日の記録や11回以上の記録はランキングの推定1RMに入らない（既存仕様）
- 体重は `bodyweight_logs`（1日1件）。筋トレMemoに体重があれば任意で取り込める
- 書き込みはSupabaseの本番プロジェクト `lombbjpiftuqkacasmzg`。本人のuser_idはメールアドレスから `auth.users` で引く。取り込みSQLやスクリーンショットの内容を共有ログやコミットに残さない
